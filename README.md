# Тестирование выпускников

Система для проведения тестов по дисциплинам техникума — с кабинетом студента, админкой и результатами в MySQL

Администратор готовит тесты и выдаёт доступ, студент заходит по логину и паролю и проходит назначенное тестирование

## Стек

| Что | На чём сделано |
| --- | --- |
| Интерфейс и серверная часть | Next.js, React, TypeScript |
| База данных | MySQL 8.4 |
| Подключение к базе | mysql2, SQL-запросы и транзакции |
| Проверка входящих данных | Zod |
| Оформление | CSS, Inter от Google Fonts в начертаниях 400, 500, 600 и 700 |
| Иконки | Lucide |
| Уведомления | Sonner |
| PDF с доступами | pdfmake |

Клиент и сервер живут в одном проекте — отдельного приложения для бэкенда нет

Prisma, Tailwind и shadcn/ui в текущей реализации не используются

## Что умеет система

- Создавать и редактировать специальности, предметы, группы и студентов
- Добавлять студентов списком и создавать учётные записи
- Выдавать последовательные логины вида `user0001` и случайные пароли из 8 символов
- Выгружать выданные доступы в TXT и альбомный PDF — название группы сверху, две тройки столбцов «ФИО / логин / пароль» на странице
- Создавать тесты, варианты, вопросы и ответы, копировать варианты и менять их названия
- Назначать опубликованные тесты группам нужной специальности
- Случайно выбирать вариант для студента и перемешивать вопросы
- Сохранять ответы при прохождении и рассчитывать оценку на сервере
- Показывать попытки в админке страницами по 40 записей, выбирать и удалять их
- Показывать результаты и столбчатые диаграммы с фильтрами по группе и предмету

Для каждого вопроса предусмотрен один правильный ответ

## Что нужно для запуска

- Node.js 24 LTS и npm
- MySQL 8.4 — установленный отдельно или запущенный через Docker Compose
- Доступ к Google Fonts во время сборки, поскольку шрифт подключён через `next/font/google`

Команды ниже выполняются из папки проекта

## Локальный запуск

### 1 — Установить зависимости

```sh
npm ci
```

### 2 — Создать настройки

Скопировать `.env.example` в `.env.local`

Для PowerShell:

```powershell
Copy-Item .env.example .env.local
```

Для Linux:

```sh
cp .env.example .env.local
```

Заполнить переменные своими значениями:

```dotenv
DATABASE_URL=mysql://testing_app:YOUR_PASSWORD@127.0.0.1:3307/technikum_testing
MYSQL_PASSWORD=YOUR_PASSWORD
MYSQL_ROOT_PASSWORD=YOUR_ROOT_PASSWORD
APP_URL=http://127.0.0.1:3000
```

`MYSQL_PASSWORD` и пароль пользователя в `DATABASE_URL` должны совпадать при запуске базы через Compose

Если в пароле есть специальные символы, в строке подключения их нужно кодировать по правилам URL

### 3 — Запустить MySQL

В проекте есть готовый вариант для локальной базы:

```sh
docker compose --env-file .env.local up -d mysql
```

База доступна только локально на порту `3307`, данные хранятся в постоянном томе `technikum-testing_mysql_data`

Если MySQL уже установлен отдельно, этот шаг пропускаем и указываем его адрес, порт, пользователя и заранее созданную базу в `DATABASE_URL`

### 4 — Подготовить таблицы и начальные данные

```sh
npm run db:setup
```

При первом запуске создаются таблицы, специальности, группы, предметы, тесты из каталога и первый администратор

Доступ администратора сохраняется в `.local/admin-access.txt`, его логин — `user0000`

Повторный запуск не перезаписывает уже инициализированную систему и первоначальную выдачу доступа

### 5 — Запустить приложение

Для разработки:

```sh
npm run dev
```

Для запуска собранной версии:

```sh
npm run build
npm run start
```

Открыть [http://127.0.0.1:3000](http://127.0.0.1:3000)

Вход общий — после авторизации система открывает кабинет по роли пользователя

## Как подготовить тестирование

1. Проверить специальность и создать в ней нужный предмет
2. Добавить выпускную группу и студентов
3. Создать пользователям доступ и сразу сохранить выдачу с паролями
4. Создать тест в предмете, заполнить варианты и проверить ключи ответов
5. В карточке предмета выбрать группы нужных выпусков и включить публикацию теста
6. Выдать студентам адрес системы, логины и пароли

Для публикации во всех вариантах должно быть одинаковое ненулевое число заполненных вопросов, а у каждого вопроса — подтверждённый правильный ответ

Доступ определяется группами предмета — опубликованный тест без назначенных групп студентам не показывается

В разделе «Пользователи» администратор может выбрать группу и выгрузить текущие пароли в PDF — для старых записей без зашифрованной копии сначала нужен сброс пароля

## Как проходит тест

По умолчанию на тест отводится 20 минут, продолжительность можно изменить в редакторе

На один тест даётся одна попытка — повторный вход возвращает ту же попытку с тем же вариантом, порядком вопросов и сохранёнными ответами

При старте сервер сохраняет снимок вопросов, ключей, шкалы оценивания и срока завершения — дальнейшее редактирование теста не меняет начатую попытку

Ответы сохраняются автоматически, между вопросами можно переключаться без перезагрузки страницы

Закрытие вкладки не останавливает время — после истечения срока учитываются только ответы, которые успели сохраниться на сервере

Студент видит оценку и число правильных ответов, правильные варианты ему не раскрываются

| Правильных ответов из 20 | Оценка |
| --- | --- |
| 18–20 | 5 |
| 15–17 | 4 |
| 12–14 | 3 |
| 0–11 | 2 |

Общие пороги — 90%, 75% и 60%, пропущенные вопросы дают 0 баллов

Администратор может удалить попытку во вкладке «Попытки» — после этого студент сможет пройти тест заново

| Дошкольная педагогика | Д4/23 |

| Математика в профессиональной деятельности учителя | Н4А/23, Н4Б/23 |

В каталоге 9 тестов, по 6 вариантов и 20 вопросов в каждом — всего 54 варианта и 1080 вопросов

Тесты импортируются черновиками, перед публикацией содержание и ключи нужно проверить ответственному за дисциплину

В дошкольной педагогике для варианта 4, вопроса 14 подтверждён первый ответ — «Обучение, которое опережает развитие и ведет его за собой»

Исходные тексты и авторские ключи перенесены из предоставленных документов, проверка актуальности учебного материала и законодательства не выполнялась

Чтобы добавить отсутствующие тесты из `seed/catalog.json` в существующую базу:

```sh
npm run db:import-tests
```

Перед добавлением скрипт сохраняет снимок данных в `.local/backups`, уже существующие тесты пропускает и ручные правки не затирает

Состав каталога не означает, что все тесты уже опубликованы в рабочей базе

## Доступ и сохранение

Пароли хранятся как PBKDF2-SHA256 с индивидуальной солью и 600000 итерациями, открытые пароли в базу не записываются

Сеансы хранятся на сервере, браузер получает HttpOnly cookie с SameSite=Strict — при HTTPS в `APP_URL` включается Secure

Роли и принадлежность попытки проверяются на сервере, для изменения данных проверяется Origin

Изменения в админке сохраняются автоматически — перед закрытием страницы стоит дождаться завершения сохранения

При конфликте изменений из разных окон система предлагает загрузить актуальные данные, локальные изменения можно предварительно скачать

`.env.local`, `.local/`, выдачи паролей и резервные копии не нужно публиковать в репозитории или размещать в открытой папке сайта

## Запуск на VPS без Docker

Next.js и MySQL можно разместить на одном сервере, отдельный сервер для клиентской части не нужен

На VPS нужны Node.js, MySQL и Nginx либо другой обратный прокси, а приложение стоит запускать отдельной службой systemd с автоматическим перезапуском

Для нашего адреса в настройках приложения:

```dotenv
APP_URL=https://attest.bip-online.ru
```

`DATABASE_URL` должен указывать на MySQL этого сервера — при стандартной установке порт обычно `3306`

Приложение слушает `127.0.0.1:3000`, Nginx принимает внешние запросы на 80/443 и передаёт их приложению

На сервере нужно настроить домен, HTTPS и резервное копирование MySQL с проверкой восстановления

`db:setup` заполняет новую базу каталогом, но не переносит текущих пользователей, ручные правки и результаты — для сохранения этих данных нужен перенос резервной копии существующей MySQL

## Что пока стоит учитывать

- Истёкшая попытка фиксируется при следующем обращении студента или загрузке данных администратором, отдельного фонового планировщика нет — срок и запрет поздних ответов проверяются сервером
- Списки попыток разбиваются на страницы в интерфейсе, при этом админка пока загружает весь набор данных
- Работа с попытками использует общую блокировку и чтение связанных данных — перед массовым запуском нужно проверить нагрузку на выбранном VPS
- Аналитика по каждому отдельному вопросу пока не реализована
- Итоговые показатели в админке обновляются кнопкой или после обновления страницы

Нагрузочная проверка на 30–40 одновременно работающих студентов ещё не проводилась, её нужно сделать до реального тестирования


## Повторная выгрузка доступов

Перед первым запуском или обновлением с этой функцией выполнить:

```sh
node scripts/setup-password-key.mjs
npm run db:setup
```

Скрипт создаёт `CREDENTIAL_ENCRYPTION_KEY` в `.env.local`, существующий ключ не заменяет — после изменения настроек приложение нужно перезапустить

Пароли для повторной выдачи хранятся в отдельной таблице как AES-256-GCM, для проверки входа по-прежнему используются хеши

Ключ нужно перенести на VPS вместе с секретными настройками и хранить отдельно от дампа базы — потеря или замена ключа сделает ранее зашифрованные пароли недоступными

При создании пользователя или сбросе пароля обновляется зашифрованная копия, удаление пользователя удаляет и её

Экспорт доступен только администратору — выбрать группу в разделе «Пользователи» и нажать «Скачать доступы в PDF» после завершения сохранения

Если исходный пароль старого пользователя неизвестен, выгрузка перечислит тех, кому нужен сброс — чужие пароли или пустые значения в PDF не подставляются

PDF формируется в браузере, сервер не создаёт и не сохраняет файлы выгрузки, ответ с паролями отправляется с запретом кеширования

## Выпуски и общие тесты

У группы отдельно хранятся год набора и год выпуска — например, ИС-4/20, набор 2020, выпуск 2024

В форме группы вводится основное название без суффикса, год набора добавляется через `/` автоматически

Переключатель выпуска в обзоре, группах, пользователях, попытках и аналитике показывает 2024, 2025, 2026 и другие годы из созданных групп, есть режим «Все годы»

Администраторы общие для всех выпусков, доступы студентов и группы для PDF отбираются по выбранному выпуску

Предмет по-прежнему принадлежит специальности, но может быть назначен нескольким группам разных выпусков — список выбирается в карточке предмета или в карточке группы

Все опубликованные тесты предмета доступны его группам, для каждого выпуска копировать тесты и вопросы не нужно

Старые назначения отдельных тестов при миграции объединяются на уровне предмета — если тесты одной дисциплины раньше назначались разным группам, теперь эти группы получат все опубликованные тесты дисциплины

У новой попытки фиксируются группа и выпуск на момент начала, поэтому перевод студента в другую группу не меняет год его старого результата

У прежних попыток без такого снимка выпуск определяется по текущей группе студента

При первом обновлении текущим группам ставится выпуск 2026, год набора и названия сохраняются — при необходимости выпуск можно поправить в карточке группы

Группы и списки студентов прошлых лет нужно добавить самостоятельно, миграция их не выдумывает

### Обновление работающего VPS

Выполнять под root, когда студенты не проходят тестирование:

```sh
systemctl stop attest
su - attest -c 'cd /var/www/attest && git pull --ff-only && npm ci && npm run typecheck && npm run build && npm run db:migrate'
```

После успешного выполнения всей команды запустить приложение:

```sh
systemctl start attest
systemctl status attest --no-pager
```

Миграция сохраняет приватную JSON-копию таблиц в `.local/backups`, добавляет колонку выпуска и таблицу связей предметов с группами, сохраняет пользователей, пароли, вопросы и попытки

Повторный `npm run db:migrate` не сбрасывает исправленные годы и назначения

Исходную базу с компьютера на работающий VPS повторно не импортируем — это затрёт изменения, уже сделанные на сервере

Для нового развёртывания `npm run db:setup` сам применяет эту миграцию перед созданием начальных данных
